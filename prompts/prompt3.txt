## Goal

When a PDF has been uploaded, the backend should be able to open the PDF and extract its text page by page.

The important flow is:

Uploaded PDF
    ↓
PDF parser
    ↓
Page-by-page text extraction
    ↓
Structured page data

For example:

{
    "document_id": "...",
    "filename": "adas.pdf",
    "pages": [
        {
            "page_number": 1,
            "text": "..."
        },
        {
            "page_number": 2,
            "text": "..."
        }
    ]
}

## Technology

Use PyMuPDF for PDF parsing.

Add the required dependency to the backend requirements.

Do not introduce another PDF parsing library unless there is a strong technical reason.

## Backend requirements

Create a clean document parsing service.

For example:

backend/app/services/document_parser.py

The parser should:

1. Accept a PDF file path.
2. Open the PDF using PyMuPDF.
3. Iterate through every page.
4. Extract text from each page.
5. Clean only obvious unwanted whitespace.
6. Preserve page boundaries.
7. Return structured page-level data.
8. Close the PDF properly after processing.
9. Handle invalid/corrupted PDFs gracefully.

Do not perform chunking in this step.

Do not generate embeddings.

Do not store anything in ChromaDB.

Do not call an LLM.

## API

Add an endpoint that allows us to extract text from an already uploaded document.

For example:

POST or GET:

/api/documents/{document_id}/extract

Choose the HTTP method that best fits the operation and explain why.

The endpoint should:

1. Find the uploaded document using its document ID.
2. Verify that the file exists.
3. Pass the file path to the document parser service.
4. Return the extracted page data.

Use a Pydantic response model.

Example response:

{
    "document_id": "...",
    "filename": "adas.pdf",
    "page_count": 3,
    "pages": [
        {
            "page_number": 1,
            "text": "..."
        },
        {
            "page_number": 2,
            "text": "..."
        }
    ]
}

Do not return unnecessary information.

## Frontend

Add a simple "Extract Text" action for uploaded documents.

For each uploaded document, provide an Extract Text button.

After extraction:

- Show page count.
- Show the extracted text.
- Clearly separate pages.
- Show page numbers.
- Show loading state while extraction is running.
- Show a useful error message if extraction fails.

Keep the UI consistent with the existing RAGLab design.

Do not build a complicated text editor or document viewer.
